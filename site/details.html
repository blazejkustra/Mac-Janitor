How Mac Janitor works

What it clears after your agents, what it leaves alone while they work and answers to common questions.

What it cleans

Each agent task tends to get its own git worktree, and each worktree grows its own dependencies and build output. Mac Janitor removes the copies that are done with. Each rule waits until an item has sat unused for a while.

  • Finished worktrees. Merged into main with nothing left to push and idle for a day, or with an open PR and untouched for 3 days, or untouched for 30 days. Your main checkout and your branches stay.
  • node_modules in worktrees nobody opened for 3 days. The worktree itself stays, so you can pick the task back up with one install.
  • Build output (node_modules, .next, Pods, Gradle, Cargo target, SwiftPM .build, Xcode build) in projects that have not changed for two weeks.
  • Caches nothing has read for a month: Xcode DerivedData and DeviceSupport, simulator caches, the pnpm store, Gradle, npx, bun and Yarn caches.
  • Docker images no container uses, and Android emulators left unused for a week.
  • Claude Code scratch folders from sessions untouched for two weeks.
  • The Trash, for items trashed over a week ago.

Safe while agents are running

Agents work for hours without you watching. Every check runs again in the moment before a delete, so a folder that came into use during the scan is skipped.

  • Anything a running process has open or works in. An agent working inside a worktree keeps that worktree, and everything in it, off the list.
  • New worktrees. A merged worktree also has to sit idle for a day, so one an agent created minutes ago stays.
  • Unpushed commits. A worktree with work no remote holds keeps it: uncommitted changes go to a patch and untracked files to an archive, both kept for 30 days, and loose commits get a git ref.
  • Anything a LaunchAgent points to, and anything you pin, with everything inside it.
  • Your documents, photos and music.
  • Large files, unless you pick them by hand. Then they go to the Trash.

Questions

Will it delete a worktree an agent is still using?

No. Right before each delete, Mac Janitor asks macOS which files and folders running processes have open or are working in. A worktree an agent is running in is skipped, and the clean lists it as in use. If that check fails, the run stops and deletes nothing.

Which agents does it work with?

Any tool that runs tasks in git worktrees, such as Claude Code, Codex, Cursor or your own scripts. It finds worktrees by asking git, wherever they live under your home folder, including hidden folders like .claude/worktrees. Scratch folder cleanup covers Claude Code sessions.

I run a dozen agents at once. Will a scheduled clean get in their way?

Scheduled cleans follow the same rules as a manual one, so anything in use is skipped. Automatic cleaning is off until you turn it on, and it can start early when free space drops below 20 GB.

Does it use AI?

No. Every decision comes from plain rules about age, git state and what is open, and you can read them in the source.

Can I undo a clean?

Deleted items are gone, except large files, which go to the Trash. Before a worktree goes, its uncommitted changes and small untracked files are saved for 30 days, and commits that no branch holds get a ref.

Why does it need Full Disk Access?

To look inside Desktop, Documents, Downloads and the Trash. It still works without it and skips those folders.

Does it run in the background?

Only if you turn on automatic cleaning. A small background job then checks every hour and cleans at the interval you choose, or sooner when free space runs low.

Does it send anything anywhere?

No. It reads your disk and asks git and gh about your own repos. Nothing leaves your Mac.
